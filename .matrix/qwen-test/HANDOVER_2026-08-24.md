## New findings this round

1. **x86-64-v3 SIGILL**: Makefile builds the daemon with `-C target-cpu=x86-64-v3`; on baseline
   x86-64 CPUs (QEMU `qemu64`, pre-AVX2 hardware) `diad-agent` dies with "Illegal instruction".
   Contradicts the ULTRA_LOW tier ("2010 netbook") promise. Either build baseline + optimize
   per-feature, or declare v3 the floor and detect+message it. Harness now passes `-cpu host`.
2. **First-boot wizard blocks headless boots**: `diad-identity-setup` holds the session until
   input/timeout on first boot; harness now pre-seeds `/var/lib/diad/identity-setup` +
   `.first-run-complete` (with correct ownership — a root-owned pre-seed broke the daemon's
   log redirect, also fixed).
3. **mako still crash-loops** (supervisor relaunches every 10 s) — unchanged from 08-18
   (`ttf-inter` missing vs `font=Inter 10`).
4. **Bloat units still failing**: krb5-kdc/kadmind, lm_sensors, sensord, sndiod,
   systemd-journal-upload — same purge recommendation as 08-18 stands.
5. tty2 manual login hang: documented (hermes), PAM/seatd interplay; not fixed.

## Fix round 2 (late 2026-08-24)

- **Chromium isolation — VERIFIED live**: `--user-data-dir=~/.local/share/diad-apps/{telegram,slack}-chromium` on the fallback branch; VM check counted 6 telegram processes carrying the flag.
- **WARN race**: `/gui-token` retry-with-backoff in `api.ts`, `launch.html`, `apps.html`; empty Bearer is never sent.
- **x86-64-v3 SIGILL**: Makefile back to baseline `x86-64` (pre-AVX2 CPUs run the daemon again; ULTRA_LOW promise intact).
- **ISO size**: monolithic `linux-firmware` → splits (intel/amdgpu/atheros/mediatek/realtek/other); nvidia/qcom/marvell/mellanox/qlogic/liquidio/cirrus/broadcom dropped. **1.69 GB → 1.39 GB (−240 MB)**. The 900 MB invariant remains out of reach while chromium (~400 MB installed) is the shell — needs a spec amendment or an epiphany-class engine return.
- **Bloat units**: masked in preset (krb5×2, lm_sensors, sensord, sndiod, journal-upload; journal-remote/git-daemon sockets disabled) → VM `systemctl --failed` now **empty**.
- **mako crash-loop root cause found (font was a red herring)**: the supervisor runs as root and launched `mako` as root — root has no D-Bus session bus (`/run/user/0/bus` absent), so mako exited instantly every cycle. Fixed: relaunch via `runuser -u diad` with diad's `XDG_RUNTIME_DIR`/`WAYLAND_DISPLAY`. Secondary: the config mako actually reads is `home/diad/.config/mako/config` (not `/etc/mako/config`); it referenced Inter, which is not in the repo pool → switched to Liberation Sans (shipped).
- **tty2 hang**: documented in `docs/TROUBLESHOOTING.md` (known issue; workaround = autologin/serial).

## Open after this round

  first poll with an empty token if `/gui-token` hasn't resolved (or transiently failed).

  `/gui-token` 2–3× with ~300 ms backoff on `!ok` before falling back to null, and never send
  `Bearer ` with an empty token (skip the call and retry instead).
